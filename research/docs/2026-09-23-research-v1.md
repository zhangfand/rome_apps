# Research v1 — file-based long-running research topics

## What changed
- New app `research`. Each topic is a folder under the Rome projects root at `research/<slug>/`
  (so it is also a webchat project): `TOPIC.md` (frontmatter + living brief), `log.md` (append-only
  timeline), `conversations/<date>-<session8>/{summary.md,transcript.md}`, `sources/<NNNN>-<slug>/`
  (original files + `meta.md` + optional `content.md`), `notes/<date>-<slug>.md`.
- Agent `research:researcher` loads context via `research:research_get_context` at conversation start
  and files material with the save/update actions.
- `agent-turn-finished` hook: for any webchat turn whose project is `research/<slug>`, rewrites the full
  transcript (from the webchat message store) and then refreshes a running summary from a small-tier
  forked turn. Serialized per session; fork sessions are ignored.
- Web UI: topic list, topic page (brief + timeline, conversations, sources, notes, search), add
  link/upload/text sources, edit brief/notes/source meta. "继续研究" opens a new chat composer bound to the
  topic project with the researcher agent and the topic page as a side widget.

## Decisions
- No database in v1 (guardian's choice): plain files, Obsidian-compatible; search is a file scan.
- Minimal frontmatter (`key: <json>` per line) to avoid a YAML dependency while staying valid YAML.
- PDF text extraction with `unpdf`; HTML reduced to text for search. Saved HTML is served as text/plain
  with a sandbox CSP so it never executes in the app origin.
- Full transcript is saved in addition to summaries (guardian's choice).

## Follow-ups
- Insight extraction / claim tracking, proactive research, DB index + semantic search.

## Fix: transcript missed the final reply
The agent-turn-finished hook can fire before the final assistant message is persisted. The hook now
re-reads the session messages after the (seconds-long) summary fork and rewrites the transcript, so the
final reply lands in `transcript.md`. Found in the pilot conversation on `agent-memory`.

## Fixes from independent verification (FAIL → re-verify)
- **Mount blocker:** `@rome-os/ui/markdown.css` pulls in KaTeX CSS whose relative `url(./fonts/…)` makes the
  host's app-stylesheet loader throw "Failed to construct 'URL'". We now import `streamdown/styles.css` and
  the `@source` lines directly and skip KaTeX CSS. (Host loader bug worth reporting separately.)
- **Concurrent writes:** all Markdown writes are atomic (temp + rename); a cross-process per-topic lock
  (`.lock` dir, stale after 30s) guards read-modify-write of TOPIC.md, source/note id allocation and
  conversation files. `log.md` appends no longer rewrite TOPIC.md; "updated" = max(frontmatter, log mtime).
  Stress test: 75 concurrent writes, brief intact, 20/20 unique source ids.
- **Empty brief:** root cause of the pilot's wiped TOPIC.md was the agent calling `research_update_brief`
  with `body` instead of `brief`, which wrote "". Actions now reject empty required text and accept common
  aliases; store/API refuse an empty brief; the agent prompt lists exact argument names. Pilot brief was
  restored from the session trace.
- Duplicate topic id → HTTP 409 with a Chinese message; timeline badges no longer wrap on mobile.
